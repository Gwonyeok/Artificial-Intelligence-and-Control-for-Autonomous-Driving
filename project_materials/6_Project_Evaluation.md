# 2. 중간발표

중간발표에서는 각 팀이 선정한 도로와 프로젝트 방향을 짧게 공유합니다.

전체 수업 시간은 약 **75분**, 총 **17개 팀**이 발표합니다.

```text
75분 / 17팀 ≈ 4.41분 / 팀
```

발표 전환 시간과 간단한 피드백 시간을 고려하여

> **팀당 발표 시간은 최대 3분**

으로 제한합니다.

## 발표 방식

- 팀당 **최대 3분**
- 3분이 되면 발표 종료
- 발표 순서는 **팀 번호 순**
- 발표자는 **1명 / 여러 명 모두 가능**
- 발표 인원은 팀에서 자유롭게 결정

## 평가 방식

중간발표에서는 **학생 상호평가를 진행하지 않습니다.**

```text
학생 평가 X

교수 / 조교 평가 O
```

중간발표의 목적은 점수를 매기는 것뿐만 아니라

> **현재 프로젝트 방향에 문제가 없는지 미리 확인하고 피드백을 받는 것**

입니다.

특히 도로 선정, 차량 interaction, 데이터 구성 등이 프로젝트 목적과 맞는지 확인할 예정입니다.

# 3. 중간발표에 포함해야 할 내용

발표 자료에는 최소한 다음 내용을 포함합니다.

## 1) 어떤 지역의 실제 도로를 선정했는가?

예:

```text
서울 광화문
수원 팔달문
강남역 인근
부산 해운대
성균관대학교 주변
```

지도 또는 실제 도로 이미지를 함께 보여주는 것을 권장합니다.

## 2) 해당 도로의 구조적 특징은 무엇인가?

예:

- 삼거리
- 사거리
- 오거리
- 회전교차로
- 합류 구간
- 분기 구간
- 다중 차선
- 차로 감소
- 비정형 교차로

단순히 "이 지역을 선택했다"가 아니라

> **자율주행 환경으로 구현했을 때 어떤 구조적 특징이 있는가?**

를 설명하면 됩니다.

## 3) 이 도로가 왜 흥미로운가?

선택한 지역이 왜 프로젝트에 적합한지 설명합니다.

예:

```text
여러 방향에서 차량이 동시에 진입
    ↓
차량 간 상호작용 증가
    ↓
속도 조절 / 양보 / 합류 / 차선 변경 필요
```

유명한 장소를 선택했다는 것만으로는 충분하지 않습니다.

> **자율주행 의사결정 문제로서 왜 의미 있는 도로인지 설득하는 것**

이 중요합니다.

## 4) 어떤 차량 interaction이 발생하는가?

도로 구조에서 발생할 수 있는 차량 간 상호작용을 설명합니다.

예:

- 직진 차량과 좌회전 차량의 interaction
- 합류 차량과 본선 차량의 interaction
- 회전교차로 진입 차량과 내부 차량의 interaction
- 차로 감소 구간에서의 양보
- 느린 차량 추월
- 다중 차선에서의 차선 변경

즉,

```text
도로 구조
    ↓
차량 interaction
    ↓
AV가 해야 하는 의사결정
```

이 자연스럽게 연결되어야 합니다.

## 5) 수집할 데이터 컬럼

프로젝트에서 수집할 데이터의 형태를 미리 정리합니다.

예:

```text
Episode
Step
Ego position
Ego speed
Ego lane
Surrounding vehicle information
Action
Reward
Next State
Done
```

> **State / Observation 관련 데이터 컬럼은 반드시 포함**

하는 방향으로 구성할 예정입니다.

중간발표에서 데이터 구성이 너무 부족하거나 이후 활용하기 어려운 형태라면 미리 피드백을 제공할 예정입니다.

## 6) 팀 이름 및 역할 분담

팀 정보와 역할 분담을 **1페이지**로 정리합니다.

예:

| 팀원 | 역할 |
|---|---|
| 팀원 A | SUMO 도로 환경 구축 |
| 팀원 B | 일반 차량 / Traffic 구성 |
| 팀원 C | AV 학습 / 평가 |
| 팀원 D | 데이터 수집 / 프로젝트 페이지 |

역할이 완전히 분리될 필요는 없습니다.

다만

> **누가 어떤 부분을 중심적으로 담당하는지 확인할 수 있도록 정리**

하면 됩니다.

를 가진 팀들을 묶어 **Session**을 구성합니다.

예:

```text

Session 3. 회전교차로 환경
```

# 7. 프로젝트 최소 필요 요건

최종 프로젝트는 다음 기준을 기본적으로 만족해야 합니다.

## 1) Collision Rate

기본 목표는

> **Collision Rate < 5%**

입니다.

예:

```text
Evaluation 100 Episode
Collision 4 Episode

→ Collision Rate = 4%
```

## 2) 목적지 완주

자율주행 차량이

```text
Start
  ↓
주어진 도로 주행
  ↓
Goal
```

까지 **문제 없이 완주할 수 있어야 합니다.**

단순히 충돌하지 않는 것뿐만 아니라

- 비정상적으로 정지하지 않는가?
- 잘못된 Route로 빠지지 않는가?
- 특정 위치에서 무한정 대기하지 않는가?

등도 함께 확인합니다.

## 3) 충분한 일반 차량 존재

자율주행 차량 혼자 주행하는 환경은 프로젝트 목표에 적합하지 않습니다.

따라서 Evaluation 시점에

> **일반 차량이 일정 수 이상 존재하는 교통 환경**

을 구성해야 합니다.

정확한 최소 차량 수는 도로 구조와 환경 크기를 고려하여 추후 확정할 수 있습니다.

중요한 것은

```text
AV 혼자 주행
```

이 아니라

```text
여러 HV + AV
    ↓
의미 있는 interaction 발생
```

이 되어야 한다는 점입니다.

## 4) 도로 형태

도로 형태에는 별도의 제한을 두지 않습니다.

```text
Open Road
Loop Road
Intersection
Roundabout
Merge / Diverge
```

모두 가능합니다.

중요한 것은 도로 형태 자체보다

> **차량 간 의미 있는 interaction이 발생하고 안정적으로 주행할 수 있는가**

입니다.

## 5) 신호등

필요한 경우 도로에 **Traffic Light를 추가해도 됩니다.**

실제 도로의 특징을 반영하기 위해 신호등이 필요한 경우 활용할 수 있습니다.

# 8. 프로젝트 평가 기준

프로젝트는 단순히 Collision Rate 하나만으로 평가하지 않습니다.

전체적인 환경 완성도와 프로젝트 수행 과정을 함께 평가합니다.

| 평가 항목 | 평가 내용 |
|---|---|
| **도로 구조 구현** | 실제 도로의 특징이 자연스럽게 반영되었는가 |
| **도로 구조의 의미** | AV가 의사결정을 해야 하는 구조적 특징이 존재하는가 |
| **Vehicle Interaction** | 일반 차량과 AV 사이에 의미 있는 interaction이 발생하는가 |
| **Simulation 안정성** | 차량이 정상적으로 주행하며 비정상적인 정체 / Teleport / 오류가 없는가 |
| **AV 주행 성능** | Collision Rate, 완주 여부 등 기본 주행 성능을 만족하는가 |
| **Traffic 구성** | 충분한 수의 일반 차량이 존재하고 자연스럽게 움직이는가 |
| **Dataset 구축** | State / Observation / Action / Reward 등의 데이터가 올바르게 저장되는가 |
| **분석 및 설명** | 환경 설계 이유, 문제점, 해결 과정을 논리적으로 설명하는가 |
| **최종 결과물** | 프로젝트 페이지, 코드, 보고서, 데이터 등을 요구된 형태로 제출했는가 |

# 9. 평가에서 중요하게 보는 것

이번 프로젝트에서는

> **누가 더 복잡한 RL 알고리즘을 만들었는가**

를 가장 중요하게 평가하지 않습니다.

기본 제공 알고리즘을 사용해도 충분합니다.

더 중요하게 보는 것은

```text
실제 도로 특징 반영
+
흥미로운 Vehicle Interaction
+
안정적인 SUMO Simulation
+
낮은 Collision Rate와 정상 완주
+
활용 가능한 데이터 수집
+
프로젝트 전체 완성도
```

입니다.

즉,

> **"왜 이 도로를 만들었고, 이 환경에서 어떤 자율주행 문제가 발생하며, 이를 얼마나 안정적으로 구현했는가?"**

를 중요하게 평가합니다.

# 10. 최종 결과물

최종적으로 각 팀은 다음 결과물을 제출해야 합니다.

## 1) 프로젝트 페이지

다른 사람이 프로젝트를 보고

```text
무엇을 만들었는지
어떤 도로인지
어떻게 실행하는지
어떤 결과가 나왔는지
```

이해할 수 있도록 구성합니다.

## 2) 코드

최종 SUMO 환경과 AV를 재현할 수 있는 코드를 제출합니다.

가능하면

```text
Environment
Training
Evaluation
Data Collection
```

코드를 구분하여 정리하는 것을 권장합니다.

## 3) 보고서

프로젝트 과정과 결과를 정리한 보고서를 제출합니다.

보고서에는 최소한 다음 내용이 포함되어야 합니다.

```text
도로 선정 이유
도로 구조
환경 구성
AV 문제 정의
학습 방법
실험 결과
분석
결론
```

## 4) 주행 데이터

프로젝트에서 수집한 주행 데이터를 다른 사람이 활용할 수 있는 형태로 정리합니다.

최소한 다음 정보가 포함되어야 합니다.

```text
State / Observation
Action
Reward
Next State / Next Observation
Done
```

추가적으로

```text
Episode
Step
Vehicle ID
Position
Speed
Lane
Surrounding Vehicle Information
```

등을 포함할 수 있습니다.

> **단순히 파일을 생성하는 것이 아니라, 다른 사람이 데이터를 이해하고 사용할 수 있는 형태로 정리하는 것**

이 중요합니다.

```text
7. 데이터가 정상적으로 저장되는가?
8. 저장한 데이터를 다시 읽고 사용할 수 있는가?
```

# 13. 프로젝트 질의응답

평가 기준과 발표 형식을 확인한 뒤 프로젝트 관련 질의응답을 진행합니다.

질문 예:
